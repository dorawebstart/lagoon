# Lagoon — власний Dynamic Island для Windows

> Робоча назва: **Lagoon**. Інші варіанти: Atoll, Isla, Pebble. Можна змінити будь-коли.
> Натхнення: відео про застосунок Island (exupery). Робимо **свій** проєкт, без чужого бренду, коду і графіки.

Цей файл є планом і завданням для Claude Code. Його кладуть у корінь репозиторію (або копіюють у `CLAUDE.md`), і Claude Code працює за ним етап за етапом.

## 2. Стек і чому саме він

| Частина | Технологія | Навіщо |
|---|---|---|
| Оболонка застосунку | **Tauri 2** | Легкий (~5–10 МБ), швидкий; ідеально для програми, яка весь час працює у фоні |
| Інтерфейс | **HTML + CSS + JavaScript** (Vite, без фреймворку) | Те, що я вже знаю; вчу веб |
| Системна частина | **Rust** (крейти `tauri`, `windows`, `tokio`, `serde`) | Доступ до Windows API: медіа, вікна, гарячі клавіші |
| Збереження налаштувань | `tauri-plugin-store` (JSON) | Колір, мова, автозапуск |
| Автозапуск | `tauri-plugin-autostart` | Острів стартує разом з Windows |
| Локальний сервер для Claude Code | `axum` (HTTP на `127.0.0.1`) | Hooks Claude Code надсилають події острову |

**Чому не Laravel.** Laravel — серверний PHP-фреймворк: він відповідає на HTTP-запити, але не вміє малювати вікно поверх робочого столу чи читати, яка пісня грає у Windows. Є NativePHP (Laravel як десктоп-застосунок), але він тягне PHP-рантайм усередину програми, а до потрібних системних API доступу все одно не дає. Laravel може знадобитися пізніше як бекенд (наприклад, проксі для ШІ-чату або синхронізація налаштувань), але для самого острова він не підходить.

### Що встановити перед стартом (Windows)
1. **Rust**: `rustup` з https://rustup.rs (toolchain `stable-x86_64-pc-windows-msvc`).
2. **Microsoft C++ Build Tools** (робоче навантаження «Desktop development with C++»).
3. **Node.js LTS**.
4. **WebView2** (у Windows 10/11 зазвичай уже є).
5. Перевірка: `rustc --version`, `cargo --version`, `node -v`.

6. **Git** (https://git-scm.com) і **GitHub CLI** `gh` (https://cli.github.com), після встановлення виконати `gh auth login`.

Claude Code: перед початком перевір, що все встановлено, і підкажи, чого бракує.

## 3. Як працює острів (архітектура)

```
┌──────────────────────── Windows ────────────────────────┐
│                                                         │
│   ┌─────── Вікно острова (Tauri, прозоре) ───────┐       │
│   │  Frontend (HTML/CSS/JS)                      │       │
│   │   - пігулка / розгорнута панель              │       │
│   │   - анімації, i18n UA/EN                     │       │
│   └──────────▲───────────────────┬───────────────┘       │
│        events│ (emit)            │ invoke (команди)      │
│   ┌──────────┴───────────────────▼───────────────┐       │
│   │  Backend (Rust)                              │       │
│   │   media.rs   ← Windows GSMTC (що грає зараз) │       │
│   │   agent.rs   ← HTTP 127.0.0.1:47823 (axum)   │◄──────┼── hooks Claude Code
│   │   window.rs  ← позиція, click-through        │       │
│   │   settings.rs                                │       │
│   └──────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────┘
```

- **Rust → JS:** Rust надсилає події (`app.emit("media:update", ...)`), фронтенд їх слухає.
- **JS → Rust:** фронтенд викликає команди (`invoke("media_play_pause")`).

### Вікно острова
- Без рамки, прозоре, **завжди поверх усіх вікон**, не видно на панелі задач (`skipTaskbar`).
- По центру верхнього краю основного монітора.
- Поза пігулкою кліки **проходять крізь вікно** до програм під ним (click-through). Вікно ловить мишу тільки над самим островом. Це найхитріша частина, тому її робимо першою і тестуємо окремо.
- Не краде фокус у відкритих програм.

## 4. MVP (версія 0.1)

### 4.1 Базовий острів
- Згорнутий стан: чорна пігулка з годинником (ГГ:ХХ). Решту стилю вирішимо пізніше, тому поки мінімалістичний чорний.
- **Наведення курсора:** плавне розкриття в панель (CSS-transition по width/height/border-radius, ~250–350 мс, easing як в iOS). Курсор пішов — згортання із затримкою ~400 мс.
- Іконка в треї з меню: «Налаштування», «Перезапустити», «Вийти».

### 4.2 Музичний плеєр
Джерело: **Windows Global System Media Transport Controls (GSMTC)** через крейт `windows`
(`Windows.Media.Control.GlobalSystemMediaTransportControlsSessionManager`).
Так острів бачить Spotify, YouTube у браузері, Apple Music, AIMP та інші програми, що інтегруються з медіапанеллю Windows.

- **Згорнутий стан, коли грає музика:** маленька обкладинка зліва, індикатор-«еквалайзер» справа.
- **Розгорнутий стан:** обкладинка, назва, виконавець, прогрес-бар з часом, кнопки ⏮ ⏯ ⏭.
- Обкладинку (thumbnail stream) Rust передає у фронтенд як base64 або data-URL.
- Оновлення через події GSMTC (`MediaPropertiesChanged`, `PlaybackInfoChanged`), а не через постійне опитування. Прогрес можна інтерполювати на фронтенді.
- Якщо нічого не грає, плеєр ховається.

### 4.3 Claude Code в острові ⭐
Мета: бачити, що робить Claude Code, і **відповідати на запити дозволу прямо з острова**, не перемикаючись у термінал.

**Як це влаштовано:**
1. Острів запускає локальний HTTP-сервер `127.0.0.1:47823` (тільки localhost) з простим токеном у заголовку.
2. У `~/.claude/settings.json` (або в проєкті `.claude/settings.json`) налаштовуємо **hooks** Claude Code. Вони викликають маленький скрипт (`lagoon-hook.exe` або PowerShell), який передає JSON події острову.
3. Події та що показує острів:
   - `UserPromptSubmit`: острів показує «Працюю…» з анімацією;
   - `PreToolUse`: коротко показує, що зараз робиться (наприклад, «Bash: git status»);
   - запит дозволу на небезпечну дію: острів **розкривається сам** і показує команду та кнопки **Дозволити / Відхилити**. Hook-скрипт чекає відповіді від острова (з таймаутом) і повертає рішення Claude Code у форматі, який очікує hook;
   - `Notification`: Claude чекає на мене, острів привертає увагу (пульсація);
   - `Stop`: «Готово ✓» на кілька секунд.
4. Якщо острів не запущено, hook нічого не ламає: виходить одразу й Claude Code поводиться як звичайно.

> Claude Code: **звір точні назви подій, формат вхідного JSON і формат відповіді для дозволів з актуальною документацією hooks** (https://docs.claude.com → Claude Code → Hooks). API могло змінитися.

### 4.4 Мови UA / EN
- Усі тексти інтерфейсу винеси в `locales/uk.json` і `locales/en.json`.
- Перемикач у налаштуваннях, зміна без перезапуску.
- Мова за замовчуванням: українська.

### 4.5 Налаштування (окреме маленьке вікно)
- Мова (UA/EN).
- Автозапуск з Windows (так/ні).
- Колір острова (поки простий вибір, повний стиль пізніше).
- Порт і токен для Claude Code + кнопка «Скопіювати конфіг hooks».

### Критерії готовності MVP
- [ ] Острів стоїть по центру вгорі, не заважає клікам по програмах під ним.
- [ ] Розкривається при наведенні, плавно згортається.
- [ ] Показує пісню зі Spotify / YouTube, кнопки працюють, обкладинка є.
- [ ] Під час роботи Claude Code видно статус; запит дозволу можна схвалити або відхилити з острова.
- [ ] Перемикач UA/EN працює.
- [ ] Автозапуск працює; програма займає < 100 МБ ОЗП.
- [ ] Зібрано інсталятор `.msi` / `.exe` (`npm run tauri build`).
- [ ] Репозиторій на GitHub: README зі скриншотом, CI зелений, реліз `v0.1.0` з інсталятором.

## 5. Порядок роботи (кроки для Claude Code)

0. **Репозиторій:** `git init`, `.gitignore`, `LICENSE`, `README.md`, `CLAUDE.md`, `gh repo create`, перший пуш. Створити milestones та issues з розділу 6.
1. **Каркас:** `npm create tauri-app@latest` (vanilla JS), запуск порожнього вікна, `ci.yml`. *Пояснити структуру `src-tauri/`, `Cargo.toml`, `main.rs`/`lib.rs`.*
2. **Вікно-острів:** прозоре, без рамки, поверх усіх, по центру зверху. Пігулка з годинником.
3. **Click-through:** миша проходить крізь прозору частину. Тестую вручну.
4. **Анімація розкриття** по наведенню (CSS + зміна розміру вікна з Rust).
5. **Трей + налаштування + i18n** (store, uk/en).
6. **media.rs:** читання GSMTC, події у фронтенд. *Пояснити `async`, `Result`, `?`, роботу з Windows API.*
7. **UI плеєра** (згорнутий і розгорнутий стан) + кнопки керування.
8. **agent.rs:** HTTP-сервер на axum, прийом подій. *Пояснити `tokio`, канали, спільний стан (`Arc<Mutex<…>>`).*
9. **Hook-скрипт** + інструкція з підключення в `settings.json` + UI статусу й кнопок дозволу.
10. **Автозапуск, збірка інсталятора**, `release.yml`, фінальна перевірка за чеклістом MVP, тег `v0.1.0`, перший GitHub Release.

Після кожного кроку: PR у `main` з описом + питання для самоперевірки по Rust.
