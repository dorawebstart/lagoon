# Lagoon — власний Dynamic Island для Windows

> Робоча назва: **Lagoon**. Інші варіанти: Atoll, Isla, Pebble. Можна змінити будь-коли.
> Натхнення: відео про застосунок Island (exupery). Робимо **свій** проєкт, без чужого бренду, коду і графіки.

Цей файл є планом і завданням для Claude Code. Він лежить у корені репозиторію, а `CLAUDE.md` посилається на нього. Claude Code працює за ним етап за етапом.

> Наступна версія: **0.4 «Інфо»** (розділ 6, «0.4 «Інфо» — наступна версія»).
> Проєкт лежить у `C:\git_project\git_project_lagoon`, репозиторій — https://github.com/dorawebstart/lagoon.
> Мої питання й відповіді — у `docs/QA.md`.

## 2. Стек і чому саме він

| Частина | Технологія | Навіщо |
|---|---|---|
| Оболонка застосунку | **Tauri 2** | Легкий (інсталятор ~1,5 МБ), швидкий; ідеально для програми, яка весь час працює у фоні |
| Інтерфейс | **HTML + CSS + JavaScript** (Vite, без фреймворку) | Те, що я вже знаю; вчу веб |
| Системна частина | **Rust** (крейти `tauri`, `windows`, `tokio`, `serde`, `axum`) | Доступ до Windows API: медіа, вікна, звук |
| Збереження налаштувань | `tauri-plugin-store` (JSON) | Колір, мова, токен |
| Автозапуск | `tauri-plugin-autostart` | Острів стартує разом з Windows |
| Локальний сервер для Claude Code | `axum` (HTTP на `127.0.0.1:47823`) | HTTP-hooks Claude Code надсилають події острову |

**Чому не Laravel.** Laravel — серверний PHP-фреймворк: він відповідає на HTTP-запити, але не вміє малювати вікно поверх робочого столу чи читати, яка пісня грає у Windows. Laravel може знадобитися пізніше як бекенд (наприклад, проксі для ШІ-чату або синхронізація налаштувань).

### Що встановлено (Windows)
1. **Rust** (`rustup`, toolchain `stable-x86_64-pc-windows-msvc`).
2. **Microsoft C++ Build Tools** («Desktop development with C++») — потрібні лінкер `link.exe` і Windows SDK.
3. **Node.js LTS**, **WebView2** (є у Windows 10/11).
4. **Git** і **GitHub CLI** `gh` (виконано `gh auth login`).

## 3. Як працює острів (архітектура)

```
┌──────────────────────── Windows ────────────────────────┐
│                                                         │
│   ┌─────── Вікно острова (Tauri, прозоре) ───────┐       │
│   │  Frontend (HTML/CSS/JS)                      │       │
│   │   - пігулка / розгорнута панель              │       │
│   │   - плеєр, статус Claude Code, i18n UA/EN    │       │
│   └──────────▲───────────────────┬───────────────┘       │
│        events│ (emit)            │ invoke (команди)      │
│   ┌──────────┴───────────────────▼───────────────┐       │
│   │  Backend (Rust)                              │       │
│   │   media.rs   ← Windows GSMTC (що грає зараз) │       │
│   │   agent.rs   ← HTTP 127.0.0.1:47823 (axum)   │◄──────┼── HTTP-hooks Claude Code
│   │   window.rs  ← позиція, click-through        │       │
│   │   tray.rs, settings.rs                       │       │
│   └──────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────┘
```

- **Rust → JS:** Rust надсилає події (`app.emit("media:update", ...)`), фронтенд їх слухає.
- **JS → Rust:** фронтенд викликає команди (`invoke("media_control", { action })`).

### Вікно острова
- Без рамки, прозоре, **завжди поверх усіх вікон**, не видно на панелі задач, **не краде фокус** (`focusable: false`).
- По центру верхнього краю основного монітора (з 0.2 — верх або низ і зсув, див. 6.5), вікно 1000×200 (розгорнута панель 380 px по центру + острівець з текстом пісні ліворуч); анімує лише CSS, прозорі частини вікна пропускають кліки.
- **Click-through:** фоновий потік у Rust кожні 30 мс перевіряє курсор і вмикає/вимикає `set_ignore_cursor_events`. Про наведення фронтенд дізнається з події `island:hover` (CSS `:hover` ненадійний, коли вікно «прозоре для миші»).
- WebView2 працює з `--disable-gpu`, вікно налаштувань створюється лише коли відкрите — так менше пам'яті (~40 МБ у Диспетчері завдань).

## 6. Що далі (після MVP)

### 0.2 «Плеєр+» — ✅ готово

**Головне правило:** кожна можливість показується **лише тоді, коли вона справді доступна** для поточного плеєра. Острів не показує кнопку, яка нічого не зробить.

#### 6.1 Повзунок гучності
- У розгорнутому плеєрі — повзунок 🔈━━━━●━━ 🔊 (+ прокрутка коліщатком над островом).
- **Гучність саме програми, що грає** (Spotify, браузер…), а не всієї системи — через Windows Core Audio: `IAudioSessionManager2` → сесія аудіо процесу плеєра → `ISimpleAudioVolume` (крейт `windows`, фіча `Win32_Media_Audio`).
- Як знайти процес: `SourceAppUserModelId` сесії GSMTC (напр. `Spotify.exe`) → аудіосесія з тим самим процесом.
- **Умова:** показуємо, якщо аудіосесію програми знайдено. Інакше — запасний варіант: загальна гучність системи (`IAudioEndpointVolume`) з підписом «Система».
- Працює і для **Spotify Free**, Premium не потрібен.
- *Rust:* COM-інтерфейси, `unsafe`, перетворення 0.0–1.0 ↔ відсотки.

#### 6.2 Перемотка пісні
- Прогрес-бар стає інтерактивним: клік або перетягування → нова позиція.
- API: GSMTC `TryChangePlaybackPositionAsync` (позиція в тиках по 100 нс).
- **Умова:** GSMTC повідомляє, чи плеєр дозволяє перемотку: `GetPlaybackInfo().Controls().IsPlaybackPositionEnabled`. Якщо `false` — прогрес-бар лишається лише для перегляду.
- Перевірити на практиці: Spotify (desktop), YouTube у Chrome/Edge (через Media Session), AIMP.
- *Rust:* нове поле `canSeek` у `MediaState`, команда `media_seek(position_ms)`.

#### 6.3 Текст пісні
- **Окремий острівець ліворуч** від основного з трьома рядками: щойно проспіваний, поточний (яскравий, жирний) і наступний (сіріші); рядки плавно їдуть угору в такт пісні. Острівець «прозорий для миші». Кнопка 🎤 у плеєрі ховає/показує його (`showLyrics` у `settings.json`).
- Джерело: **[LRCLIB](https://lrclib.net)** — безкоштовний відкритий API без ключа: `GET https://lrclib.net/api/get?artist_name=…&track_name=…&album_name=…&duration=…` → `syncedLyrics` (LRC з таймкодами) або `plainLyrics`.
- **Умова:** острівець і кнопка з'являються, лише якщо знайдено **синхронізований** текст. Звичайний (без міток часу) поки лише зберігаємо в кеші — у три рядки його не вписати.
- Знайдені тексти кешуються на диску (папка кешу застосунку → `lyrics/<хеш>.json`). Пошук: точний `/api/get`, якщо немає — `/api/search` з найближчою тривалістю.
- Офіційний текст Spotify не використовуємо: публічного API для нього немає.
- *Rust:* HTTP-клієнт (`reqwest`), `async`, розбір формату LRC.

#### 6.4 Умови і Spotify Premium
| Можливість | Через що | Spotify Free | Spotify Premium | Браузер (YouTube) |
|---|---|---|---|---|
| Назва, обкладинка, ⏮ ⏯ ⏭ | Windows GSMTC | ✅ | ✅ | ✅ |
| Гучність програми | Windows Core Audio | ✅ | ✅ | ✅ (гучність браузера) |
| Перемотка | GSMTC, якщо `IsPlaybackPositionEnabled` | перевірити | перевірити | ✅ зазвичай |
| Текст пісні | LRCLIB | ✅ | ✅ | ✅ |
| ❤️ лайк, черга, пристрої | **Spotify Web API** (OAuth) | ❌ | ✅ | — |

- Усе, що робимо через Windows, **не залежить від підписки**.
- **Spotify Web API** (лайк, додати в чергу, перемкнути пристрій) потребує входу через Spotify (OAuth) і для керування відтворенням — **Premium**. Це окремий, необов'язковий крок у майбутньому: кнопка «Підключити Spotify» в налаштуваннях, а функції з'являються лише якщо акаунт Premium (`GET /v1/me` → `product: "premium"`).
- Ключі Spotify (Client ID) — тільки в локальних налаштуваннях, не в репозиторії.

#### 6.5 Позиція острова
Зараз острів завжди по центру верхнього краю. У 0.2 його можна поставити **вгорі або внизу** і зсунути вліво/вправо.

**Край (верх / низ)**
- Вибір у налаштуваннях: «Вгорі» / «Внизу».
- Позиція рахується від **робочої області монітора** (`Monitor::work_area()` у Tauri) — тобто внизу острів стоїть **над панеллю задач**, а не під нею; так само враховується панель задач, перенесена вгору чи вбік.
- Коли острів **унизу**, він **розкривається вгору**: вікно (1000×200) прив'язане нижнім краєм до низу робочої області, а пігулка в CSS вирівняна знизу (клас `.island--bottom` на `<body>`: `align-items: flex-end`, `transform-origin: bottom center`). Анімація та сама, лише в дзеркальному напрямку.

**Перетягування мишею**
- Пігулку можна взяти мишею і тягнути **вздовж краю** (вліво/вправо), а також **перекинути з верху на низ** і навпаки.
- Під час перетягування вікно йде за курсором; при відпусканні острів **«прилипає» до найближчого краю** (верх чи низ — за тим, у якій половині робочої області відпустили), горизонтальний зсув обмежується межами робочої області.
- **Перетягування ≠ клік:** рух починається лише після зсуву курсора більше ніж на **~5 px** від точки натискання. Якщо поріг перейдено — `click` після `pointerup` гаситься, тож кнопки плеєра (⏮ ⏯ ⏭) і дозволів (Дозволити / Відхилити) **не спрацьовують випадково**. Додатково: перетягування не починається, якщо натиснули саме на кнопку чи повзунок (гучність, перемотка) — тягнемо лише за «тіло» пігулки.
- Реалізація (зроблено так): фронтенд (`drag.js`) ловить `pointerdown` / `pointermove`, рахує поріг і викликає `island_drag_start`; далі все робить Rust (`position.rs`) у потоці, що стежить за курсором: кожні 10 мс зсуває вікно за курсором (`cursor_position()`), а відпускання кнопки помічає сам через `GetAsyncKeyState` — так перетягування не обривається, навіть якщо сторінка втратить мишу. Наприкінці — подія `island:drag-end`.
- Біля лівого краю екрана текст пісні перескакує **праворуч** від острова (Rust надсилає `lyricsSide` у події `island:placement`).
- Поки триває перетягування, click-through вимкнено (вікно має отримувати мишу), а hover-розкриття призупинено, щоб острів не розгортався посеред руху.

**Збереження**
- Позиція зберігається в `settings.json` (`tauri-plugin-store`): `islandEdge: "top" | "bottom"` і `islandOffset` — зсув центру острова від центру робочої області **у частках її ширини** (−0.5…0.5), щоб позиція не «з'їжджала» після зміни роздільної здатності чи масштабу.
- Під час старту позиція відновлюється; якщо збережене значення виходить за межі екрана — острів обмежується межами робочої області.
- Кнопка **«Скинути позицію»** в налаштуваннях → верх, по центру (`islandEdge: "top"`, `islandOffset: 0`).

**Click-through і hover в обох положеннях**
- Зона наведення (`set_hit_region`) рахується від фактичного положення пігулки у вікні: унизу пігулка в нижній частині вікна, тож прямокутник відповідно зсувається; решта вікна лишається прозорою для миші.
- Перевірити: верх/низ × згорнуто/розгорнуто × запит дозволу (острів розкривається сам) × панель задач з автоприховуванням.

*Rust:* новий модуль `position.rs` — розрахунок позиції з краю і зсуву, «прилипання», обмеження межами (`f64::clamp`); `enum IslandEdge { Top, Bottom }` з `serde` (серіалізація в рядок `"top"` / `"bottom"`); спільний стан перетягування через `Mutex` у `State`.

### 0.3 «Стиль» — ✅ готово

**Головне правило:** острів стає гарнішим, але не важчим. Робимо без відеокарти (WebView2 з `--disable-gpu`), тож кожен ефект має бути дешевим для процесора.

#### Умови (критерії готовності 0.3)
- Процесор у спокої (нічого не грає) — як у 0.2; під час музики з анімацією краю — не вище ~1–2 %.
- Пам'ять — не більше +10 % до v0.2 (тією ж метрикою, що в PR #47).
- Коли нічого не грає або острів не видно, анімація краю не працює (немає подій з Rust, немає `requestAnimationFrame`).
- Windows «Показувати анімацію» вимкнено (`prefers-reduced-motion`) — край не рухається.
- Усі налаштування застосовуються **одразу**, без перезапуску, і зберігаються в `settings.json`.
- Працює вгорі й унизу, біля бокових країв, з острівцем тексту ліворуч і праворуч.
- Усі тексти UI — через `uk.json` / `en.json`.

#### 6.6 Теми
- **Класична** (чорна), **Графіт** (сіра), **Скло** (напівпрозорий темний фон + тонка світла рамка), а також **свій колір** (вибір з палітри, є з 0.1).
- «Скло» — імітація: справжнє розмиття Windows (Acrylic / Mica) діє на все вікно (1000 px), а не лише на пігулку.
- Технічно: усі кольори острова, острівця з текстом, кнопок і тексту — CSS-змінні (`--island-bg`, `--island-fg`, `--island-muted`, `--accent`…); тема = набір значень, клас на `<body>`.

#### 6.7 Колір з обкладинки (акцент)
- **Перемикач** «Колір з обкладинки» — працює з будь-якою темою.
- Фронтенд бере домінантний колір обкладинки (canvas, зменшена копія картинки) і фарбує ним еквалайзер, прогрес-бар, повзунок гучності, хвилю краю, поточний рядок тексту пісні.
- Занадто темний чи сірий колір — піднімаємо яскравість, щоб його було видно на чорному.
- Без обкладинки або перемикач вимкнено — стандартний акцент теми.

#### 6.8 Розміри острівців
Зараз розміри задані в CSS жорстко (основний острів 380 px у розгорнутому стані, острівець з текстом пісні 280 px, вікно 1000 px). Налаштування «Розмір» (**за замовчуванням — як зараз**):
- **Масштаб основного острова** — повзунок 90–130 % (100 %): пропорційно збільшує пігулку, обкладинку, кнопки й шрифти (одна CSS-змінна `--scale`).
- **Ширина острівця з текстом** — 220–420 px (280 px), щоб довгі рядки не обрізалися «…».
- **Розмір шрифту тексту пісні**.
- **Rust підганяє розмір вікна** під вибрані розміри: нічого не обрізається, а прозора частина вікна не більша, ніж треба. Розрахунок спільний з позицією острова (6.5, `position.rs`): `ISLAND_HALF_WIDTH`, `LYRICS_SPACE` і `EDGE_GAP` стають залежними від масштабу.
- Кнопка **«Скинути розміри»**.
- Зміна розміру перетягуванням за край — не робимо: острів і так «прозорий для миші» й перетягується (6.5), а повзунки простіші й надійніші.

#### 6.9 «Живий» край — хвиля (обрано варіант Б)
- Тонкі смужки-«хвиля» вздовж краю пігулки, що дивиться всередину екрана: острів **вгорі** — по нижньому краю, **внизу** — по верхньому.
- Рухаються в такт **гучності** програми, що грає.
- Джерело: Rust, `IAudioMeterInformation` аудіосесії плеєра (та сама сесія, що й для гучності, `audio.rs`) — пікове значення 0.0–1.0. Записувати звук не потрібно.
- Rust читає рівень ~30 разів на секунду **лише поки грає музика** і шле подію `audio:level`; фронтенд згладжує значення і малює смужки (кожна з власною фазою, щоб хвиля виглядала живою).
- Обмеження: це рівень гучності, а не частоти. Справжній еквалайзер за частотами (запис звуку системи — WASAPI loopback — і FFT) важчий; лишаємо як ідею на потім.
- Перемикач «Хвиля» в налаштуваннях (увімкнено за замовчуванням).
- *Rust:* COM `IAudioMeterInformation`, фоновий потік з умовою «грає / не грає», канал для зупинки потоку.

#### 6.10 Полірування анімацій (рішення з прототипів)
- **Розкриття — плавне, без пружини** (360 мс) + короткий **желейний** трус (пружину пробували — прибрали); **згортання** — швидше (260 мс), без пружини. Вікно 216 px заввишки — запас для анімацій, щоб нічого не обрізалось.
- **Затримка перед розкриттям** 150 мс — курсор, що пролітає повз, острів не розкриває.
- **Вміст** розкритого острова «виринає» (з 96 %, після того як острів виріс); **острівець з текстом** виїжджає з-за острова.
- **Крапля** на подію (нова пісня, «Готово ✓» від Claude Code): відривається від краю, що дивиться всередину екрана. «Рідкий» SVG-фільтр (`goo`) — лише на шарі під островом і лише ~0,9 с.
- `prefers-reduced-motion` — без желе, краплі й хвилі.
- Окремого налаштування «Анімації» не додаємо.

#### 6.11 Сховати / показати острів (додано за запитом)
- **Ctrl+Alt+L** з будь-якої програми (плагін `tauri-plugin-global-shortcut`) і пункт «Сховати острів / Показати острів» у меню трею.
- Поки острів схований, Rust не відстежує курсор і не міряє рівень звуку.
- Запит дозволу від Claude Code показує схований острів сам.
- Стан не зберігається: після перезапуску острів знову видно.
- Обмеження: поверх гри в **ексклюзивному** повноекранному режимі Windows не показує вікон; у режимі «вікно без рамки» працює.

### 0.4 «Інфо» — наступна версія ⭐

**Головне правило:** острів показує корисну інформацію, але лишається легким і нічого не надсилає без потреби. Рішення — з макетів 13.11.2026.

#### Умови (критерії готовності 0.4)
- Процесор у спокої — як у 0.3 (~0,02 %); пам'ять — не більше +5 % до v0.3.1 (та сама метрика, release з release).
- Погода оновлюється раз на 30 хв і **не оновлюється, поки острів схований**; батарея — за подіями Windows, без опитування.
- **Жодних ключів у репозиторії:** Open-Meteo працює без ключа.
- **Приватність місця:** місто вводить користувач; координати — лише в `settings.json`, на сервер ідуть округлені (~1 км, 2 знаки після коми). Місце за IP не визначаємо. «Моє розташування» — служба розташування Windows, яка сама питає дозвіл.
- **Розкладка:** Rust лише читає мову активного вікна; натискання клавіш не перехоплює (жодних keyboard hooks).
- Без інтернету — остання збережена погода з підписом «оновлено о…»; старша за 3 години — ховаємо.
- На ПК без батареї заряд не показується.
- Усе застосовується одразу; тексти — через `uk.json` / `en.json`; працює вгорі й унизу.

#### 6.12 Погода
- Джерело: **[Open-Meteo](https://open-meteo.com)** (безкоштовно, без ключа): `api.open-meteo.com/v1/forecast` — температура, «відчувається як», код погоди, вітер (швидкість у **м/с**, напрямок), вологість, схід і захід сонця. Пошук міста — `geocoding-api.open-meteo.com/v1/search`.
- **Пігулка** (варіант Б): іконка й температура поруч з годинником **лише коли нічого не грає**; під час музики пігулка як зараз.
- **Розкритий острів:** вкладки «Плеєр / Погода» вгорі; коли нічого не грає — одразу «Погода». Плитки: **вітер з компасом** (м/с, напрямок), **вологість**, **схід і захід сонця**, **батарея** (6.13). Тиску немає; вибору одиниць немає (°C, м/с).
- **Налаштування:** пошук міста, кнопка «Моє розташування», перемикач «Погода».
- *Rust:* модуль `weather.rs` — `reqwest` (як у `lyrics.rs`), `serde` для JSON, кеш на диску, фоновий таймер; команди `weather_current`, `weather_search_city`; подія `weather:update`. Розташування — WinRT `Windows.Devices.Geolocation.Geolocator`.

#### 6.13 Батарея
- Відсоток заряду і час: **від батареї — скільки ще протримається, на зарядці — скільки до повного**.
- Показ (варіант В): **% з іконкою завжди в пігулці**, коли нічого не грає, **і** острів на 3 с розкривається при підключенні / відключенні зарядки та на 20 % і 10 % («Низький заряд · 20 % · ще 48 хв»); плитка у вкладці «Погода».
- Джерело: WinRT `Windows.Devices.Power.Battery::AggregateBattery()` → `GetReport()` (залишок і повна ємність, швидкість заряду/розряду в мВт), подія `ReportUpdated`. Час рахуємо самі: залишок ÷ швидкість розряду; до повного — (повна − залишок) ÷ швидкість заряду. Немає батареї — `Status = NotPresent`, нічого не показуємо.
- *Rust:* модуль `battery.rs`, подія `battery:update`; обробник WinRT-події (замикання, яке Windows викликає сама).

#### 6.14 Розкладка клавіатури
- Індикатор мови (`UA`, `EN`…) з'являється в пігулці **на 1,5 с** при зміні розкладки; постійно не показується.
- Джерело: `GetForegroundWindow` → `GetWindowThreadProcessId` → `GetKeyboardLayout` → код мови. Перевірка в потоці, що вже стежить за курсором (кожні ~200 мс), подія `keyboard:layout` — лише коли мова змінилась.
- Секунди в годиннику — **не робимо** (рішення 13.11.2026).

## 8. Відкриті питання (вирішимо по ходу)
- Остаточна назва.
- ~~Стиль згорнутого острова?~~ Вирішено (план 0.3): теми Класична / Графіт / Скло / свій колір + колір з обкладинки; «живий» край — хвиля вздовж краю (варіант Б).
- Справжній еквалайзер за частотами (WASAPI loopback + FFT) замість хвилі від гучності — після 0.3, якщо хвилі буде мало.
- Кілька моніторів. Поки що (0.2) острів живе **лише на основному моніторі**, а перетягування обмежене його робочою областю. Відкрите питання на потім:
  - дозволити перетягнути острів на інший монітор (тоді зберігати ще й ідентифікатор монітора — назву/позицію з `available_monitors()` — і повертатися на основний, якщо того монітора більше немає);

  - різний масштаб (DPI) моніторів: зсув у частках ширини це частково вирішує, але треба перевірити на практиці.
