# Lagoon — власний Dynamic Island для Windows

> Робоча назва: **Lagoon**. Інші варіанти: Atoll, Isla, Pebble. Можна змінити будь-коли.
> Натхнення: відео про застосунок Island (exupery). Робимо **свій** проєкт, без чужого бренду, коду і графіки.

Цей файл є планом і завданням для Claude Code. Він лежить у корені репозиторію, а `CLAUDE.md` посилається на нього. Claude Code працює за ним етап за етапом.

> **Стан (12.11.2026):** ✅ **MVP 0.1 готовий** — реліз [v0.1.0](https://github.com/dorawebstart/lagoon/releases/tag/v0.1.0).
> Наступна версія: **0.2 «Плеєр+»** (розділ 6).
> Проєкт лежить у `C:\git_project\git_project_lagoon`, репозиторій — https://github.com/dorawebstart/lagoon.
> Мої питання й відповіді — у `docs/QA.md`.

## 2. Стек і чому саме він

| Частина | Технологія | Навіщо |
|---|---|---|
| Оболонка застосунку | **Tauri 2** | Легкий (інсталятор ~1,5 МБ), швидкий; ідеально для програми, яка весь час працює у фоні |
| Інтерфейс | **HTML + CSS + JavaScript** (Vite, без фреймворку) | Те, що я вже знаю; вчу веб |
| Системна частина | **Rust** (крейти `tauri`, `windows`, `tokio`, `serde`, `axum`) | Доступ до Windows API: медіа, вікна, звук |
| Збереження налаштувань | `tauri-plugin-store` (JSON) | Колір, мова, токен |
| Автозапуск | `tauri-plugin-autostart` | Острів стартує разом з Windows |
| Локальний сервер для Claude Code | `axum` (HTTP на `127.0.0.1:47823`) | HTTP-hooks Claude Code надсилають події острову |

**Чому не Laravel.** Laravel — серверний PHP-фреймворк: він відповідає на HTTP-запити, але не вміє малювати вікно поверх робочого столу чи читати, яка пісня грає у Windows. Laravel може знадобитися пізніше як бекенд (наприклад, проксі для ШІ-чату або синхронізація налаштувань).

### Що встановлено (Windows)
1. **Rust** (`rustup`, toolchain `stable-x86_64-pc-windows-msvc`).
2. **Microsoft C++ Build Tools** («Desktop development with C++») — потрібні лінкер `link.exe` і Windows SDK.
3. **Node.js LTS**, **WebView2** (є у Windows 10/11).
4. **Git** і **GitHub CLI** `gh` (виконано `gh auth login`).

## 3. Як працює острів (архітектура)

```
┌──────────────────────── Windows ────────────────────────┐
│                                                         │
│   ┌─────── Вікно острова (Tauri, прозоре) ───────┐       │
│   │  Frontend (HTML/CSS/JS)                      │       │
│   │   - пігулка / розгорнута панель              │       │
│   │   - плеєр, статус Claude Code, i18n UA/EN    │       │
│   └──────────▲───────────────────┬───────────────┘       │
│        events│ (emit)            │ invoke (команди)      │
│   ┌──────────┴───────────────────▼───────────────┐       │
│   │  Backend (Rust)                              │       │
│   │   media.rs   ← Windows GSMTC (що грає зараз) │       │
│   │   agent.rs   ← HTTP 127.0.0.1:47823 (axum)   │◄──────┼── HTTP-hooks Claude Code
│   │   window.rs  ← позиція, click-through        │       │
│   │   tray.rs, settings.rs                       │       │
│   └──────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────┘
```

- **Rust → JS:** Rust надсилає події (`app.emit("media:update", ...)`), фронтенд їх слухає.
- **JS → Rust:** фронтенд викликає команди (`invoke("media_control", { action })`).

### Вікно острова
- Без рамки, прозоре, **завжди поверх усіх вікон**, не видно на панелі задач, **не краде фокус** (`focusable: false`).
- По центру верхнього краю основного монітора (з 0.2 — верх або низ і зсув, див. 6.5), розмір вікна = розмір розгорнутої панелі (420×200); анімує лише CSS.
- **Click-through:** фоновий потік у Rust кожні 30 мс перевіряє курсор і вмикає/вимикає `set_ignore_cursor_events`. Про наведення фронтенд дізнається з події `island:hover` (CSS `:hover` ненадійний, коли вікно «прозоре для миші»).
- WebView2 працює з `--disable-gpu`, вікно налаштувань створюється лише коли відкрите — так менше пам'яті (~40 МБ у Диспетчері завдань).

## 6. Що далі (після MVP)

### 0.2 «Плеєр+» — наступна версія ⭐

**Головне правило:** кожна можливість показується **лише тоді, коли вона справді доступна** для поточного плеєра. Острів не показує кнопку, яка нічого не зробить.

#### 6.1 Повзунок гучності
- У розгорнутому плеєрі — повзунок 🔈━━━━●━━ 🔊 (+ прокрутка коліщатком над островом).
- **Гучність саме програми, що грає** (Spotify, браузер…), а не всієї системи — через Windows Core Audio: `IAudioSessionManager2` → сесія аудіо процесу плеєра → `ISimpleAudioVolume` (крейт `windows`, фіча `Win32_Media_Audio`).
- Як знайти процес: `SourceAppUserModelId` сесії GSMTC (напр. `Spotify.exe`) → аудіосесія з тим самим процесом.
- **Умова:** показуємо, якщо аудіосесію програми знайдено. Інакше — запасний варіант: загальна гучність системи (`IAudioEndpointVolume`) з підписом «Система».
- Працює і для **Spotify Free**, Premium не потрібен.
- *Rust:* COM-інтерфейси, `unsafe`, перетворення 0.0–1.0 ↔ відсотки.

#### 6.2 Перемотка пісні
- Прогрес-бар стає інтерактивним: клік або перетягування → нова позиція.
- API: GSMTC `TryChangePlaybackPositionAsync` (позиція в тиках по 100 нс).
- **Умова:** GSMTC повідомляє, чи плеєр дозволяє перемотку: `GetPlaybackInfo().Controls().IsPlaybackPositionEnabled`. Якщо `false` — прогрес-бар лишається лише для перегляду.
- Перевірити на практиці: Spotify (desktop), YouTube у Chrome/Edge (через Media Session), AIMP.
- *Rust:* нове поле `canSeek` у `MediaState`, команда `media_seek(position_ms)`.

#### 6.3 Текст пісні
- Кнопка «Текст» 🎤 у плеєрі → панель з текстом; **синхронізований** (рядок підсвічується в такт), якщо такий є.
- Джерело: **[LRCLIB](https://lrclib.net)** — безкоштовний відкритий API без ключа: `GET https://lrclib.net/api/get?artist_name=…&track_name=…&album_name=…&duration=…` → `syncedLyrics` (LRC з таймкодами) або `plainLyrics`.
- **Умова:** кнопка з'являється, лише якщо текст знайдено. Немає синхронізованого — показуємо звичайний. Немає жодного — кнопки немає.
- Кешувати знайдені тексти на диску (щоб не питати сервер щоразу).
- Офіційний текст Spotify не використовуємо: публічного API для нього немає.
- *Rust:* HTTP-клієнт (`reqwest`), `async`, розбір формату LRC.

#### 6.4 Умови і Spotify Premium
| Можливість | Через що | Spotify Free | Spotify Premium | Браузер (YouTube) |
|---|---|---|---|---|
| Назва, обкладинка, ⏮ ⏯ ⏭ | Windows GSMTC | ✅ | ✅ | ✅ |
| Гучність програми | Windows Core Audio | ✅ | ✅ | ✅ (гучність браузера) |
| Перемотка | GSMTC, якщо `IsPlaybackPositionEnabled` | перевірити | перевірити | ✅ зазвичай |
| Текст пісні | LRCLIB | ✅ | ✅ | ✅ |
| ❤️ лайк, черга, пристрої | **Spotify Web API** (OAuth) | ❌ | ✅ | — |

- Усе, що робимо через Windows, **не залежить від підписки**.
- **Spotify Web API** (лайк, додати в чергу, перемкнути пристрій) потребує входу через Spotify (OAuth) і для керування відтворенням — **Premium**. Це окремий, необов'язковий крок у майбутньому: кнопка «Підключити Spotify» в налаштуваннях, а функції з'являються лише якщо акаунт Premium (`GET /v1/me` → `product: "premium"`).
- Ключі Spotify (Client ID) — тільки в локальних налаштуваннях, не в репозиторії.

#### 6.5 Позиція острова
Зараз острів завжди по центру верхнього краю. У 0.2 його можна поставити **вгорі або внизу** і зсунути вліво/вправо.

**Край (верх / низ)**
- Вибір у налаштуваннях: «Вгорі» / «Внизу».
- Позиція рахується від **робочої області монітора** (`Monitor::work_area()` у Tauri) — тобто внизу острів стоїть **над панеллю задач**, а не під нею; так само враховується панель задач, перенесена вгору чи вбік.
- Коли острів **унизу**, він **розкривається вгору**: вікно 420×200 прив'язане нижнім краєм до низу робочої області, а пігулка в CSS вирівняна знизу (клас `.island--bottom` на `<body>`: `align-items: flex-end`, `transform-origin: bottom center`). Анімація та сама, лише в дзеркальному напрямку.

**Перетягування мишею**
- Пігулку можна взяти мишею і тягнути **вздовж краю** (вліво/вправо), а також **перекинути з верху на низ** і навпаки.
- Під час перетягування вікно йде за курсором; при відпусканні острів **«прилипає» до найближчого краю** (верх чи низ — за тим, у якій половині робочої області відпустили), горизонтальний зсув обмежується межами робочої області.
- **Перетягування ≠ клік:** рух починається лише після зсуву курсора більше ніж на **~5 px** від точки натискання. Якщо поріг перейдено — `click` після `pointerup` гаситься, тож кнопки плеєра (⏮ ⏯ ⏭) і дозволів (Дозволити / Відхилити) **не спрацьовують випадково**. Додатково: перетягування не починається, якщо натиснули саме на кнопку чи повзунок (гучність, перемотка) — тягнемо лише за «тіло» пігулки.
- Реалізація: фронтенд ловить `pointerdown` / `pointermove` / `pointerup` (з `setPointerCapture`), рахує поріг і викликає Rust-команди `island_drag_start` / `island_drag_end`; сам рух вікна робить Rust за позицією курсора (`GetCursorPos`) у потоці, який уже стежить за курсором для click-through, — так рух плавний і не залежить від того, що WebView «бачить» мишу.
- Поки триває перетягування, click-through вимкнено (вікно має отримувати мишу), а hover-розкриття призупинено, щоб острів не розгортався посеред руху.

**Збереження**
- Позиція зберігається в `settings.json` (`tauri-plugin-store`): `islandEdge: "top" | "bottom"` і `islandOffset` — зсув центру острова від центру робочої області **у частках її ширини** (−0.5…0.5), щоб позиція не «з'їжджала» після зміни роздільної здатності чи масштабу.
- Під час старту позиція відновлюється; якщо збережене значення виходить за межі екрана — острів обмежується межами робочої області.
- Кнопка **«Скинути позицію»** в налаштуваннях → верх, по центру (`islandEdge: "top"`, `islandOffset: 0`).

**Click-through і hover в обох положеннях**
- Зона наведення (`set_hit_region`) рахується від фактичного положення пігулки у вікні: унизу пігулка в нижній частині вікна, тож прямокутник відповідно зсувається; решта вікна лишається прозорою для миші.
- Перевірити: верх/низ × згорнуто/розгорнуто × запит дозволу (острів розкривається сам) × панель задач з автоприховуванням.

*Rust:* новий модуль `position.rs` — розрахунок позиції з краю і зсуву, «прилипання», обмеження межами (`f64::clamp`); `enum IslandEdge { Top, Bottom }` з `serde` (серіалізація в рядок `"top"` / `"bottom"`); спільний стан перетягування через `Mutex` у `State`.

## 8. Відкриті питання (вирішимо по ходу)
- Остаточна назва.
- Стиль згорнутого острова (чорний з «рідким» краєм / скло / інше).
- Кілька моніторів. Поки що (0.2) острів живе **лише на основному моніторі**, а перетягування обмежене його робочою областю. Відкрите питання на потім:
  - дозволити перетягнути острів на інший монітор (тоді зберігати ще й ідентифікатор монітора — назву/позицію з `available_monitors()` — і повертатися на основний, якщо того монітора більше немає);
  - чи показувати острів на кожному моніторі одночасно (кілька вікон — більше пам'яті);
  - різний масштаб (DPI) моніторів: зсув у частках ширини це частково вирішує, але треба перевірити на практиці.
- Повзунок гучності: керувати гучністю програми чи системи за замовчуванням? (план: програми, система — запасний варіант).
- Де показувати текст пісні: у розгорнутому острові (обмежене місце) чи окремою більшою панеллю під островом?
- Чи потрібна взагалі інтеграція зі Spotify Web API (вхід через акаунт), чи досить можливостей Windows.
- Підпис інсталятора (зараз SmartScreen попереджає «невідомий видавець»).
